---
title: Troubleshooting
description: Common symptoms in the dashboard and in API calls, with their causes and what to do.
---

Find your symptom, read the likely cause, then follow the action. For how a call travels, see
[How a request travels](/docs/how-it-works).

## APIs

| Symptom | Cause | What to do |
|---|---|---|
| A new API is saved, but calls to it fail. | A new API starts as **Draft**. It is not live until its status is **Active**. | Open the API and choose **Activate**. |
| **Create API** is refused. | Your tenant reached the API limit of its plan: 3 for Free, 10 for Starter, 50 for Pro. Enterprise has no limit. | Ask a tenant administrator to move the tenant to a larger plan. See [Roles, audit and tenants](/docs/roles-audit-tenants). |
| The sync status says **Pending** right after a save. | Saving returns before the gateway is updated. The gateway update runs afterwards, and the status updates on the page. | Wait a moment. The status becomes **Synced** or **Failed**. |
| The sync status says **Failed**. The API page shows "Gateway sync failed:" and an error. | The gateway did not accept the API definition. The error text says why. | Read the error and fix the setting it names. Saving the API syncs it again. The **API sync status** card on the Dashboard also lists failed APIs with a **Retry** button, which needs permission to sync APIs (`api:sync`). |

## Keys and calls

A call that is refused for its key or quota appears in **Traffic** with a 4xx status. A call that the edge firewall
stops, if it is set to block, never reaches the gateway and leaves no record. See [Analytics and traffic](/docs/analytics-and-traffic).

| Symptom | Cause | What to do |
|---|---|---|
| A call gets **401**. | The API requires a key and the call sent none, or the key has expired and the nightly check has not removed it yet. | Send the key in the API's authentication header, normally `Authorization`. Open the key in **Keys** and check that its status is **Active**, not **Expired**. |
| A call gets **403**. | The key was revoked, or expired and was removed. Or a quota is used up (the response says **Quota exceeded**): the key's, its plan's or the tenant's. Or an endpoint rule blocks the path, or the API lists allowed endpoints and this path is not one of them. | Check the key status in **Keys**. Open the key to see its **Quota**. Then check the endpoint rules of the API. |
| A call gets **429**. | A rate limit was reached: the key's, the plan's, the API's or an endpoint's. A rate limit on an endpoint uses one counter shared by all keys, so one busy key can exhaust it for the others. | In **Traffic**, set **Exact status** to 429 to see when it happens. Open the key to see its **Rate limit** and **Quota**. |

## Analytics

| Symptom | Cause | What to do |
|---|---|---|
| A page says "Analytics pipeline not receiving data". | The recording of requests is down, its tables are not created yet, or no request has arrived yet. The hint on the card says which. | Tell the people who run the platform which hint you see. If no request has arrived, send traffic through the gateway. |
| A notice says "Analytics collection is paused" above the figures. | New requests are not being recorded, so the figures are stale. The notice gives the time of the last record. | Tell the people who run the platform. |
| Figures show a dash or "No data". | Nothing was recorded in the range, or a filter hides it. Or **Do not track** is on in the API's **Edit** sheet, so its requests are not recorded. | Choose a longer range. On the Dashboard, look for a **Showing** chip and choose **Show all APIs**. On **Traffic**, choose **Reset filters**. |
| Figures look too low. | **Do not track** is on for an API, or the recorder was down for a while. | Check **Do not track** in the API's **Edit** sheet, and the notices above the figures. |
| "Failed to load data". | The request for the figures failed. | Use the **Retry** button on the card. |

## Captured requests and Request search

Captured requests exist only for APIs that have **Detailed recording** on. The switch is **Record full detail**,
in the Designer of the API, and it is off by default.

| Symptom | Cause | What to do |
|---|---|---|
| The **Traffic** tab of an API says "Detailed recording is off". | Detailed recording is off and nothing was ever captured. | Turn it on in the Designer. The tab appears only if you hold `api:update`. |
| The **Traffic** tab says "No traffic has been captured for this API in this window." | No request was captured in that window. Requests made while recording was off are not captured. | Send a request with recording on, then check again. |
| The **Traffic** tab says "Captured traffic can't be shown". | The analytics store is unavailable, or its redaction safeguard is not active. Nothing is shown. | Use **Retry**. If it stays, tell the people who run the platform. |
| Request search says "No captured requests in this window." | No API has captured requests in the range. | Turn on detailed recording for the API, or widen the range. |
| Request search says "No captured request matches these filters in this window." | Nothing matches. Word search does not stem, so `fund` does not find `funds`. A `path:` filter matches the start of the path. A secret is stored as `[REDACTED]`, so its value cannot be found. | Remove filters one at a time. Try the exact word. See [Searching traffic](/docs/searching-traffic). |
| Request search says the search index has not started yet. | Indexing has not begun. | Wait. Captured requests appear shortly after they are recorded. |
| A recent request is missing, and the page shows "Indexed up to" an earlier time. | The search only covers requests up to that time. | Look again in a moment. |
| A filter chip is red. | The filter is not understood. The reason is under the box. | Fix or remove the chip. |
| A message under the box says "At most 8 filters per search." or "At most 3 body-word filters per search." | The search has too many filters. No chip turns red for this. | Remove filters. Words must also have 3 letters or more. |
| "That search is too broad to finish in time." | The search matches too many requests. | Add a status, an API, a shorter range or a more specific word. |
| "You do not have access to search captured requests." | The server refused the search during your session, for example because your role changed. | Ask an administrator for `analytics:read` and `api:update`. Without them from the start, the page shows the **No access** card instead. |

## "No access"

A page that shows "No access" tells you the permission you lack, in the form `resource:action`. Send it to a tenant
administrator, who can grant it through a role. If a tenant page says "This tenant does not exist, or you are not a
member of it", you are not a member of that tenant. See [Roles, audit and tenants](/docs/roles-audit-tenants).
